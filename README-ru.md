# Telegram to Obsidian AI Agent

[English](README.md) | **Русский**

Личный Telegram-бот, который превращает сообщения, идеи и файлы в
структурированные заметки Obsidian.

Telegram служит точкой входа, Hermes Agent обрабатывает сообщения, а хранилище
Obsidian сохраняет ваши знания. Бот находит подходящие заметки, дополняет их
или создаёт новые, добавляет теги и связывает записи между собой.

Хранилище синхронизируется между сервером и ноутбуком через Syncthing. Вы
можете работать с заметками в Obsidian, пока бот продолжает сохранять новые
записи на сервере.

Для чтения с телефона предусмотрено мини-приложение внутри Telegram: в нём
доступны список заметок, поиск и просмотр вложений. В полночь бот подводит
итоги дня и сохраняет их в ежемесячный журнал.

## Возможности

### Сохранение мыслей и идей

Отправьте боту сообщение - остальное он сделает сам:

- передаст текст агенту Hermes Agent;
- найдёт в хранилище заметку на ту же тему;
- дополнит существующую заметку или создаст новую;
- добавит дату и теги во фронтматтер - блок метаданных в начале файла;
- оформит упоминания существующих заметок как `[[вики-ссылки]]`.

Новые заметки по умолчанию получают теги `inbox` и `telegram`. Дополнительные
теги можно указать прямо в сообщении: например, `#идея #работа`.

После сохранения бот отвечает коротким подтверждением:

```
Создал заметку «Идеи для бизнеса».
```

### Поиск информации в интернете

Если сообщение требует внешней информации - например, содержит вопрос,
незнакомый термин или запрос о ценах и новостях, - агент выполняет поиск через
MCP-сервер DuckDuckGo.

Найденная информация сохраняется в заметке вместе со ссылкой на источник.

### Вложения

Бот сохраняет фотографии, документы, видео и голосовые сообщения в папку
`attachments` внутри хранилища и добавляет ссылку на файл в заметку:

```text
![[2026-10-22_photo_abc.jpg]]
```

### Ежедневные итоги

Каждый день в полночь по часовому поясу владельца бот собирает информацию о
записях за прошедший день и добавляет краткий итог в файл текущего месяца.

В Telegram приходит уведомление с кнопкой для открытия мини-приложения. Сам
итог остаётся в хранилище.

### Мини-приложение в Telegram

Открывайте заметки прямо из меню чата с ботом, без запуска Obsidian. В
мини-приложении доступны:

- список заметок;
- поиск;
- чтение заметок и просмотр изображений;
- ежедневные итоги в верхней части списка;
- оформление в соответствии со светлой или тёмной темой Telegram.

### Доступ только для владельца

Бот обрабатывает сообщения только от разрешённого Telegram ID. Сообщения
остальных пользователей молча игнорируются.

## Команды

| Команда | Описание |
| --- | --- |
| `/start`, `/help` | краткая справка о боте |
| `/status` | последние сохранённые заметки |
| `/search кофе` | поиск по названиям и содержимому заметок |
| `/inbox` | заметки с тегом `inbox` |
| `/undo` | отмена последней записи бота |
| `/undo confirm` | подтверждение удаления созданной ботом заметки, если после создания её изменили |
| `/summary` | создание итога за вчерашний день |
| `/summary 2026-10-20` | создание итога за указанную дату |
| `/language` | доступные языки интерфейса |
| `/language ru` | переключение на русский язык |
| `/language en` | переключение на английский язык |

Команда `/undo` учитывает тип последнего изменения:

- если бот дописал текст, добавленный блок удаляется;
- если бот перезаписал заметку, восстанавливается прежнее содержимое;
- если бот создал заметку, она удаляется.

Если созданную ботом заметку успели изменить, для её удаления потребуется
отдельное подтверждение: `/undo confirm`.

Язык сохраняется в базе отдельно для каждого пользователя. По умолчанию
используется английский, а для владельца бота - русский. Мини-приложение
использует тот же язык, что и бот.

## Итоги дня

В полночь по часовому поясу владельца агент анализирует записи за прошедший
день и сохраняет итог в ежемесячный файл, например `october_2026.md`:

```markdown
---
date: 2026-10-01
tags: [journal, daily]
---

# Октябрь 2026

## 2026-10-21

Заметка «Идеи для бизнеса»: идея открыть кофейню в районе.
Заметка «Дневник»: запись о прогулке и прочитанной книге.
```

В итог попадает краткое описание того, что было записано в каждую заметку за
день.

- Каждый день оформляется отдельным разделом.
- Дни без записей пропускаются.
- Язык итогов соответствует языку владельца.
- В чат отправляется только короткое уведомление с кнопкой перехода в
  мини-приложение.
- В мини-приложении итоги отображаются над списком заметок.

Если бот не работал в полночь, пропущенные итоги создаются после следующего
запуска.

## Защита записей при синхронизации

Syncthing может обновлять файлы одновременно с агентом. Чтобы снизить риск
повреждения заметок и потери изменений, запись выполняется с несколькими
уровнями защиты:

- **Атомарная запись.** Новое содержимое сначала сохраняется во временный
  файл, который затем переименовывается поверх целевого. Это позволяет
  избежать чтения частично записанной заметки.
- **Ожидание после изменений.** Если `fs.watch` обнаруживает недавнее
  изменение файла, запись откладывается на секунду.
- **Повторные попытки.** Если файл заблокирован, бот повторяет запись каждые
  500 мс.
- **Проверка результата.** После записи файл перечитывается. Если
  синхронизатор успел изменить его содержимое, операция повторяется. При
  добавлении текста учитывается существующее содержимое.
- **Отслеживание конфликтов.** Конфликтные копии Syncthing с именами вида
  `*.sync-conflict-*` отображаются в отчёте.

Пути MCP-инструментов разрешаются относительно корня хранилища: агент не может
записывать файлы за его пределами.

Агент, который формирует ежедневный итог, использует те же инструменты, но его
промежуточные изменения откатываются. В результате сохраняется только
обновление файла месяца.

## Установка на сервер

Понадобится Linux-сервер с установленными Docker и Docker Compose.

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/danii1kq/telegram-to-obsidian_ai-agent.git
cd telegram-to-obsidian_ai-agent/deploy
```

### 2. Настройте переменные окружения

Создайте `.env` из примера и ограничьте доступ к файлу:

```bash
cp .env.example .env
chmod 600 .env
```

Заполните параметры:

| Переменная | Описание |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен бота, полученный у [@BotFather](https://t.me/BotFather) |
| `ALLOWED_TELEGRAM_ID` | Telegram ID владельца, которому разрешено пользоваться ботом |
| `TELEGRAM_MODE` | режим получения сообщений: `polling` по умолчанию или `webhook` при наличии публичного HTTPS-адреса |
| `TELEGRAM_WEBHOOK_URL` | публичный HTTPS-адрес webhook |
| `TELEGRAM_WEBHOOK_SECRET` | секрет для проверки запросов webhook от Telegram |
| `VAULT_HOST_PATH` | путь к хранилищу на сервере, например `/opt/obsidian-vault` |
| `LLM_API_KEY` | API-ключ провайдера модели |
| `HERMES_MODEL` | основная модель; по умолчанию `beam-free` |
| `HERMES_FALLBACK_MODEL` | резервная модель на случай, если основная не ответит |
| `MINI_APP_URL` | публичный HTTPS-адрес мини-приложения |
| `MINI_APP_TOKEN` | токен для доступа к мини-приложению из обычного браузера; передаётся в URL |
| `DEFAULT_LANGUAGE` | язык для пользователей, которые ещё не выбрали его; по умолчанию `en` |
| `OWNER_LANGUAGE` | язык владельца; по умолчанию `ru` |
| `PUID` / `PGID` | UID и GID владельца файлов хранилища; по умолчанию `1000` |

### 3. Подготовьте хранилище и запустите контейнеры

Если вы используете стандартные значения `PUID` и `PGID`:

```bash
mkdir -p /opt/obsidian-vault
sudo chown -R 1000:1000 /opt/obsidian-vault
docker compose up -d --build
```

Путь к папке должен соответствовать `VAULT_HOST_PATH`, а права - значениям
`PUID` и `PGID`.

### 4. Проверьте запуск

```bash
docker compose ps
docker compose logs -f app
```

Первая сборка может занять некоторое время: в образ устанавливается Hermes
Agent. При последующих сборках используются кэшированные слои.

Готовый образ также доступен в GitHub Container Registry:

```bash
docker pull ghcr.io/danii1kq/telegram-to-obsidian_ai-agent:latest
```

## Мини-приложение

Мини-приложение открывается кнопкой в меню чата с ботом. Оно позволяет искать и
читать заметки, просматривать изображения и ежедневные итоги.

Фронтенд находится в папке `web/`, собирается через Vite и раздаётся тем же
процессом, что и бот.

### Авторизация

При открытии внутри Telegram мини-приложение передаёт подписанные данные
пользователя. Бэкенд проверяет подпись с помощью токена бота.

Для доступа из обычного браузера используется токен владельца:

```text
https://<your-host>/?token=<MINI_APP_TOKEN>
```

### Публикация через HTTPS

Для мини-приложения требуется публичный HTTPS-адрес. В проекте предусмотрен
скрипт настройки туннеля Cloudflare.

Из корня репозитория выполните:

```bash
bash deploy/tunnel.sh --install
```

Скрипт запускает туннель, отслеживает его адрес и записывает его в файл
окружения деплоя.

Тот же туннель можно использовать для webhook бота. Для этого укажите:

```text
TELEGRAM_MODE=webhook
TELEGRAM_WEBHOOK_URL=https://<адрес-туннеля>/webhook
```

## MCP-сервер хранилища

Инструменты для работы с хранилищем доступны отдельным пакетом
`@danii1kq/vault-mcp`. Их можно использовать с любым MCP-клиентом, независимо
от Telegram-бота.

Установка и запуск:

```bash
npm install -g @danii1kq/vault-mcp
OBSIDIAN_VAULT_PATH=/path/to/vault vault-mcp
```

Подробности - в документации пакета.

## Синхронизация с ноутбуком

Хранилище синхронизируется через Syncthing. Бот работает с серверной копией, а
Obsidian на ноутбуке - с локальной.

### 1. Откройте интерфейс Syncthing на сервере

Веб-интерфейс работает на порту 8384 и не открыт в интернет. Для подключения
создайте SSH-туннель:

```bash
ssh -L 8384:127.0.0.1:8384 user@your-server
```

Затем откройте в браузере:

```text
http://127.0.0.1:8384
```

### 2. Свяжите устройства

- В интерфейсе сервера выберите `Actions` -> `Show ID` и скопируйте ID
  устройства.
- Установите Syncthing на ноутбук.
- Добавьте сервер как удалённое устройство, указав его ID.
- Подтвердите подключение ноутбука в интерфейсе сервера.

### 3. Настройте общую папку

- На сервере добавьте папку с путём `/vault`, например с именем `obsidian`.
- Предоставьте ноутбуку доступ к этой папке.
- На ноутбуке примите приглашение и выберите локальную папку для синхронизации.
- Откройте эту папку в Obsidian как хранилище.

После синхронизации заметки будут доступны на ноутбуке, а бот продолжит
работать на сервере.

## Обновление

В каталоге `deploy` выполните:

```bash
git pull
docker compose up -d --build
```

Для автоматизированного обновления предусмотрен скрипт `deploy/deploy.sh`. Если
новый контейнер не проходит проверку, скрипт возвращает предыдущий образ.

Из корня репозитория:

## Безопасность

В проекте предусмотрены следующие меры защиты:

- Бот обрабатывает сообщения только от Telegram ID, указанного в
  `ALLOWED_TELEGRAM_ID`.
- Секреты хранятся в `deploy/.env` на сервере и не добавляются в Git.
- API-ключ модели подставляет локальный прокси; агент не получает его напрямую.
- MCP-инструменты ограничены папкой хранилища и не могут записывать файлы за её
  пределами.
- API мини-приложения проверяет подписанные данные Telegram, а при доступе из
  браузера требует токен владельца.
- Webhook проверяет секрет, передаваемый Telegram с каждым запросом.
- Файлы заметок и вложений хранятся в хранилище владельца.
